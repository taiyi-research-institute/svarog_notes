零知识证明 - 直观定义

零知识证明是 Prover 与 Verifier 之间的一个协议, 让以下两件事同时成立:

(a) 有说服力. 若命题为真, Prover 能让 Verifier 接受. 若命题为假, Verifier 几乎都不可能接受.

(b) 零知识. Verifier 跑完整个协议后, 除了 "这个命题是真的" 以外, 学不到任何东西.

⚠️ 条款 (b) 绝不仅仅是 "没泄露秘密 witness", 而是 "没泄露任何可计算的信息". 判断标准是:

```
任何人靠自己就能编出一份合法 (*1) 的聊天记录 (*2), 不需要 Prover 参与.

(*1) 合法: 符合协议所约定的数学构造.
(*2) 这就是 transcript.
```

以上判断标准的直觉是:

```
如果存在一种零知识的方法能够编出 transcript, 那就说明协议不存在信息泄露.
```



隐私协议是正确且存在模拟器的协议. 正确性保护 Verifier, 存在模拟器保护 Prover. 

为什么 “可模拟” 就等于 “没多学到信息” ?

难点在于, “没多学到信息” 本身没法直接定义. 什么叫 “知识”, 什么叫 “零”, 没法量化. 模拟范式用一个对照绕开这个哲学问题. 它不去刻画 “信息” 是什么, 而是说:

凡是多出来的, 都会让编造成为不可能. 如果视图能从理想输出单独算出来, 那么视图里就不可能含理想输出之外的任何东西. 因此用不着列 "不泄露 $w$, 不泄露 $w$ 的首位, 不泄露 $w$ 是否为素数, ..." 这张无穷清单, 可模拟性直接断言: 不泄露关于秘密的任何可计算函数. 它用一个存在性命题堵死了所有可能的偷学方式.



transcript (通信记录) 协议各方之间来回传的全部消息序列.

view (视图) 某一方所能看到的一切信息. view 包含: 他的输入, 他摇的随机数, transcript 里他收到和他发出的信息. 一般只提他收到的.

ideal output (理想输出) 一方有权合法知道的结果, 是模拟器唯一的输入. 对于零知识证明, ideal output 就是命题的真值.

ideal functionality (理想功能) 一个绝不作弊的可信第三方, 它直接完成任务再把结果交给各方.
