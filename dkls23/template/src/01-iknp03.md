title: "IKNP03 OT 扩展"

朴素位分解 OT 的每一个比特都要跑一次椭圆曲线二选一 OT, 太贵. IKNP03 给出的解法叫 **OT 扩展** — 椭圆曲线只在 keygen 阶段跑$\kappa$次, 签名阶段用这几颗种子衍生出任意多的 OT 实例.

本篇只做到半诚实安全. 一致性检查手段是另一条主线, 见 KOS15 恶意安全 (KOS15) 和 SoftSpokenOT (SoftSpokenOT).

# 1. Base OT 协议

本协议在 ECDSA Keygen 阶段跑$\kappa$次,$\kappa$是安全参数, 通常取 128 或 256. 下面写第$i$次 ($i\in[\kappa]$) 的规格.

输入:

* Base OT Sender 现场摇一对$\lambda$-比特种子$\left(k^0_i, k^1_i\right)$, 本文取$\lambda=\kappa$.
* Base OT Receiver 现场摇选择比特$s_i \in \left\{0,1\right\}$.

输出: 

* Base OT Sender 无输出.
* Base OT Receiver 得到所选的那颗种子$k^{s_i}_i$.

安全承诺:

* Base OT Sender 得不到$s_i$.
* Base OT Receiver 得不到另一颗种子$k^{1-s_i}_i$.

这就是 MtA 与 Base OT 里朴素二选一 OT 的规格, 只是消息特化成了随机种子. 实施本篇不讲: DKLs23 用的是安全定义更清晰的 Endemic OT (Endemic OT), 而不是 MtA 与 Base OT 里的朴素实施.

# 2. Payload OT 协议

本协议在 ECDSA Sign 阶段跑 2 次, 分别用于算$k\gamma$和$\mathtt{sk}\cdot\gamma$的 MtA (见 MtA 与 Base OT). 每次一口气跑$m$个 OT 实例,$m$可以远大于$\kappa$, 这正是 "扩展" 二字的由来.

## 2.1. 规格 ($\approx$ 理想功能)

输入:

* Payload OT Receiver 持有 Base 两侧种子$\left(k^0_i, k^1_i\right)$,$i\in[\kappa]$, 以及 Payload 选择向量$b \in \left\{0,1\right\}^m$.
* Payload OT Sender 持有 Base 选择向量$s$, Base 单侧种子$k^{s_i}_i$, 以及$m$对 Payload 消息$\left(M^0_j, M^1_j\right)$,$j\in[m]$.

 以上安排意味着 Base OT Sender 成为 Payload OT Receiver, Base OT Receiver 成为 Payload OT Sender. 后文简称 Receiver / Sender, 一律指 Payload OT 侧的角色.

输出:

* Receiver 得到每个实例选中的那一条, 即$M^{b_j}_j$,$j\in[m]$.
* Sender 无输出.

安全承诺: 与朴素二选一 OT 相同, 只是一口气承诺$m$个实例 —

* 对每个$j$, Receiver 得不到没选的那条$M^{1-b_j}_j$;
* Sender 得不到$b$的任何比特.

安全假设:

* 双方半诚实, 即都按剧本出牌. 恶意方能造成什么破坏, 见末节 "半诚实的边界".
* 第一批输入来历合规: 种子确实是 Base OT 协议的输出, 其安全承诺未被破坏. 这是本协议全部安全性的根, 尤其是 "Receiver 不知道$s$" 这一半.
* 对称原语可靠: PRG 的输出与真随机不可区分, Hash 视作随机预言机, 对称加密 Enc 可靠.

## 2.2. 实施

### 2.2.(1) Receiver 计算和发送 "半密钥"

双方约定一个 PRG$F: \left\{0,1\right\}^* \rightarrow \left\{0,1\right\}^m$, 实现上可选 AES-CTR, ChaCha20 等.

Receiver 把$2\kappa$个种子按下式拉长为 2 个$\kappa\times m$矩阵 — 行数$\kappa$是种子条数, 列数$m$是 OT 实例数. 记号:$A_{i,*}$表示矩阵$A$的第$i$行,$A_{*,j}$表示第$j$列.

$$
\begin{align*}
t^0_{i,*}:=F\left(\mathtt{sid},\,\mathtt{tag},\, k^0_i\right), \\
t^1_{i,*}:=F\left(\mathtt{sid},\,\mathtt{tag},\, k^1_i\right). \\
\end{align*}
$$

 保密纪律: 域分离. 由持久秘密衍生出临时秘密, 必须掺入域分离参数, 使得每次衍生都得到不同的临时秘密; 选取参数务必保证, 同样的一组参数绝不重复出现. 本篇的域分离参数共 3 项:

*$\mathtt{sid}$隔离签名会话, 即本场 ECDSA 签名的会话 ID;
*$\mathtt{tag}$隔离同一场签名内的 2 次运行, 取 "k-gamma" / "sk-gamma" 之类的常量;
*$j$隔离 OT 实例, 在后文 (keys) 处登场.

往后读到入参罗嗦的$F$或$\mathtt{Hash}$, 先把域分离参数摘出去, 剩下的才是干货.

然后以$t^0 \oplus t^1$的各行 (row) 为密钥, 对$b$进行异或加密, 如下式.

$$
{u}:={t}^0 \oplus {t}^1 \oplus b. \tag{umat}
$$

其中, 算子 "$\oplus$" 是逐元素异或; 向量$b$被当成$1\times m$矩阵, 并重复$\kappa$行, 从而与$t^0 \oplus t^1$形状相同.

最后把$u$发给 Sender.

### 2.2.(2) Sender 计算完整密钥, 发送密文

#### 2.2.(2.1) 准备密钥前体

Sender 把$\kappa$个种子拉长为 1 个$\kappa\times m$矩阵:

$$
t_{i,*} := F\left(\mathtt{sid},\,\mathtt{tag},\,k^{s_i}_i\right).
$$

然后计算

$$
{q} := {t} \oplus \left(s\odot {u}\right). \tag{qmat}
$$

式中, 算子 "$\odot$" 是按位与.$s$是$\kappa\times 1$的列向量, 广播成$\kappa \times m$矩阵.

探讨一下 (qmat).

* 当$s_i = 0$时,$u_{i,*}$被丢弃, 从而$q_{i,*}=t_{i,*}^0$.
* 当$s_i=1$时,$t_{i,*}=t_{i,*}^1$,$u_{i,*}=t_{i,*}^0\oplus t_{i,*}^1\oplus b$, 从而$q_{i,*}=t_{i,*}^0\oplus b$.

两种情形合并为下式, 标签 i7t = interpret. 式中$s\times b$是外积/矩阵乘:$s$是$\kappa\times 1$矩阵,$b$是$1\times m$矩阵, 输出第$(i,j)$元素为$s_i \odot b_j$.

$$
q = {t}^0\oplus(s\times{b}). \tag{q.i7t}
$$

到 (q.i7t) 为止, 一切都是按行算的. 从这里开始换方向, 按列看 — 第$j$个 OT 实例只认第$j$列. 把 (q.i7t) 限制到第$j$列, 得到下式. 式中$b_j$是单个元素, 需要广播到跟$s$一样的形状, 即$\kappa$-维向量.

$$
q_{*,j}=t^0_{*,j}\oplus \left(b_j \odot s\right). \tag{qcol}
$$

#### 2.2.(2.2) 得到密钥和密文

基于 (qcol) 得到 Sender 的两把密钥如下.

$$
\begin{align*}
K^0_j &:= \mathtt{Hash}\left(
    \mathtt{sid},~\mathtt{tag},~j,~q_{*,j}\right
), \\
K^1_j &:= \mathtt{Hash}\left(
	\mathtt{sid},~\mathtt{tag},~j,~q_{*,j}\oplus s\right
). \tag{keys} \\\end{align*}
$$

探讨一下 (qcol, keys).

* 当$b_j=0$时,
  *$K^0_j=\mathtt{Hash}\left(\mathtt{sid},~\mathtt{tag},~j,~t^0_{*,j}\right)$,
  *$K^1_j=\mathtt{Hash}\left(\mathtt{sid},~\mathtt{tag},~j,~t^0_{*,j}\oplus s\right)$.
* 当$b_j=1$时,
  *$K^0_j=\mathtt{Hash}\left(\mathtt{sid},~\mathtt{tag},~j,~t^0_{*,j}\oplus s\right)$,
  *$K^1_j=\mathtt{Hash}\left(\mathtt{sid},~\mathtt{tag},~j,~t^0_{*,j}\right)$.
* 无论$b_j$取何值, Receiver 在 (umat) 引入的$b$都因 "异或偶数次" 而消掉.

最后, Sender 仿照 MtA 与 Base OT 的 (ot-cts) 计算密文, 发给 Receiver:

$$
C_j^\delta := \mathrm{Enc}\left(K_j^\delta,~M_j^\delta\right),~~\delta=0,1.
$$

### 2.2.(3) Receiver 解开所选密文

对每对密文$C_j^0, C_j^1$, Receiver 计算密钥

$$
K_j^{b_j}:=\mathtt{Hash}\,\big(
\mathtt{sid},\,\mathtt{tag},\, j,\, t_{*,j}^0\big).
$$

凭此密钥解开$C_j^{b_j}$得到$M_j^{b_j}$, 解不开另一个密文$C_j^{1-b_j}$. 协议至此结束.

## 2.3. 小结

### 2.3.1. 核对安全承诺

"Receiver 得不到另一个消息", 归约到 "Receiver 算不出另一个密钥", 归约到 "Receiver 不知道$s$". 最后一句是整个 IKNP 安全性的落脚点, 后续所有对 IKNP 的攻击 (见 KOS15 恶意安全) 都是在想办法窥探$s$.

"Sender 不知道选什么", 归约到 "Sender 不知道$b$", 归约到 "(umat) 一次一密异或加密" 的安全性.

### 2.3.2. 与 MtA 与 Base OT 对比思路

本篇在比特矩阵上做异或, 上一篇在椭圆曲线上做点乘, 看似风马牛不相及, 其实有着同一副骨架. 逐项对照如下.

(1. 半密钥, Receiver 发)

* 上一篇$B=\beta G + dA$, 选项是$d$. 公式 (ot-bcom).
* 本篇$u={t}^0 \oplus {t}^1 \oplus b$, 选项是$b$. 公式 (umat).

(2. 掩码, 职责是在半密钥里保护选项)

* 上一篇$\beta G$, 均匀随机.
* 本篇$t^0\oplus t^1$, 一次一密.

(3. 全密钥的原像. Sender 枚举$\delta\in\left\{0,1\right\}$)

* 上一篇$\alpha (B-\delta A)$.
* 本篇$q_{*,j}\oplus(\delta\odot s)$.

(4. 两个原像之差)

* 上一篇$\alpha A$, 即$\alpha^2 G$.
* 本篇$s$.

(5. Receiver 算得出的原像)

* 上一篇$\beta A$, 条件为$\delta=d$.
* 本篇$t_{*,j}^0$, 条件为$\delta=b_j$.

(6. 另一个原像为何算不出)

* 上一篇归约到 CDH 难题.
* 本篇归约到 Base OT 藏住 s.

我从以上 6 点提炼出两条可以迁移的原则. 我希望, 无论有多么繁复/晦涩的 OT 框架摆在眼前, 都能在这两个原则的审视下祛魅.

**原则一: 半密钥是被一次性掩码遮蔽的选项.**

不论怎样构造 OT 协议, Receiver 只有在半密钥里加入选项, 才能命中他所选的全密钥原像. 而新鲜掩码负责混淆, 使得无论选项取何值, 半密钥的分布不变.

**原则二: 全密钥原像追求 "等差" 结构, 公差是 Sender 专属的秘密.** ^080cf8

Sender 不知道选项, 却要备齐两把密钥, 出路是让两个候选原像相差一个与选项无关的固定量. 我称这个固定量为 "公差", 上一篇是$\alpha A$, 本篇是$s$. 等差结构使得 Sender 枚举出的两个原像里恰有一个是 Receiver 所选的, 而另一个差着 "公差". 于是 "Receiver 得不到另一个原像" 归约为 "Receiver 不知道公差". 最后, 原像喂给 Hash 变成全密钥, 把 "原像差一个公差" 升格为 "两把密钥各自独立", 并掺入域分离参数 ($\mathtt{sid}, \mathtt{tag}, j$).

这两条原则后面还用得上: KOS15 恶意安全 的一致性检查通过后, 密钥派生与本篇一字不差; SoftSpokenOT 把二选一换成$2^k$选一, "等差对" 变成 "等差数列", 公差在那篇叫$\Delta$; 到了 随机 VOLE, 干脆不再取密钥, 把等差结构本身当产品输出 ($\Delta$-correlation).

### 2.3.3. 点评性能

Payload OT 的密钥交换基于 "异或消去律" 以及 "异或加密的安全性", 而不是像 Base OT 那样基于椭圆曲线. 二者在同等比特长度下的安全性是相同的, 但异或的计算量更低.

### 2.3.4. 指出持久化数据

本协议服务于 ECDSA 签名, 因此需考虑把哪些变量持久存储. 以下放进 keystore, 其余未提及的一律不放:

* Sender 的种子选择向量$s$和已选种子$k_i^{s_i}$.
* Receiver 的成对种子$(k_i^0, k_i^1)$.

# 3. 半诚实的边界

以上就是 IKNP03 的全部, 它只在双方都按照规矩出牌时才是安全的. 破绽有两处, 各自对应后续的一条主线; 第 (3) 条不是破绽, 是换根基的另一条路线, 一并列在这里:

**(1) Sender 照单全收$u$.** 公式 (qmat) 里, Sender 没有任何手段检查$u$的每一行是否编码了同一个$b$. 恶意 Receiver 逐行掺入不同的$b$, 就能窥探$s$对应的比特; 而一旦拿到$s$, 由公式 (keys) 他就能同时算出两把密钥, OT 彻底失效. 具体攻击和 KOS15 的挑战-响应对策, 见 KOS15 恶意安全.

**(2) Receiver 无法检查密文.** 恶意 Sender 可以只把一条消息加密对, 另一条填垃圾, 再从下游成败反推$b_j$— 也就是 MtA 与 Base OT 末尾说的 selective failure. 对策见 随机 VOLE 的校验负载.

**(3) SoftSpokenOT**. 这条路线不再修补 IKNP 的二选一结构, 而是把底层换成$2^k$选一的 PPRF, 拿计算量换带宽 ---- (umat) 的行数从$\kappa$降到$\kappa/k$. 见 PPRF 与 GGM 树 和 SoftSpokenOT.
